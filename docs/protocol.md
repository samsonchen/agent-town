# Protocol v1

The protocol between the agent-town mod (sender) and a agent-town app (receiver). It has no platform-specific parts except the location of the endpoint file. The JSON Schema for every event goes in `protocol/schema/`, and recorded event streams for tests go in `protocol/fixtures/`.

## Transport

- HTTP/1.1 `POST` to `http://127.0.0.1:<port>/v1/events`
- Header `Authorization: Bearer <token>`
- Header `Content-Type: application/json`
- Body: a batch

```json
{
  "protocol": 1,
  "events": [ { ...event }, { ...event } ]
}
```

Responses:

| Status | Meaning | Sender does |
|---|---|---|
| 204 | Accepted | Nothing |
| 400 | Malformed request or batch | Nothing |
| 401 | Wrong token | Re-read the endpoint file; send the batch once more if the app is there |
| 426 | Unsupported protocol version | Stop sending for this session; show one toast |
| Connection refused, timeout | App not running | Re-read the endpoint file at once. If the app is there (it may have restarted on another port), send the batch once more, unless it is older than 60 s; otherwise drop it |

The sender sends a batch at most twice: the one retry above, after reconnecting. Otherwise a lost event is acceptable; the heartbeat and later events correct the state. While not connected, the sender reads the endpoint file every 2 s. On connecting, it sends `session.open` again, with the session's context and open ticket, unless a `session.open` is already queued, so receivers must accept a repeated `session.open`.

## Endpoint file

The app writes this file when its server starts and deletes it on quit (only if the file still holds its own `pid`). Mode 0600. The sender ignores a file whose `protocol` it does not support.

```json
{
  "protocol": 1,
  "port": 51234,
  "token": "random-32-bytes-base64url",
  "pid": 4242,
  "app": "agent-town",
  "appVersion": "0.1.0"
}
```

| Platform | Path |
|---|---|
| macOS | `~/Library/Application Support/agent-town/endpoint.json` |
| Windows | `%APPDATA%\agent-town\endpoint.json` (the Windows app is future; town-link already looks here) |
| Linux | `$XDG_STATE_HOME/agent-town/endpoint.json` (future) |

A mod cannot ask Claude Code for the OS, so town-link uses the Windows path when `APPDATA` is set, which macOS never sets, and the macOS path otherwise.

On Windows, mode 0600 does not apply. The file is protected by where it is: `%APPDATA%` is in the user's own profile, which by default only that user (and administrators) can read. The Windows app should not loosen the folder's permissions.

## Event envelope

Every event has these fields:

| Field | Type | Notes |
|---|---|---|
| `type` | string | One of the types below |
| `sessionId` | string | Claude Code session ID |
| `seq` | integer | Per session, starts at 1, increases by 1. The receiver uses it to order events and spot gaps. |
| `ts` | integer | Sender clock, Unix milliseconds |
| `projectId` | string | Hash of the project identity (see [architecture.md](architecture.md)) |

## Event types

### `session.open`

| Field | Type | Notes |
|---|---|---|
| `projectName` | string | Repository or folder name |
| `surface` | string | `terminal`, `desktop`, `vscode`, `mobile`, `headless` |
| `ccVersion` | string | Claude Code version |
| `locale` | string, optional | If the mod can read it |
| `model` | string, optional | The session's model at start, from `$.session.model()` |

### `session.close`

| Field | Type | Notes |
|---|---|---|
| `reason` | string | `clear`, `resume`, `logout`, `prompt_input_exit`, `other` (from Claude Code) |

### `heartbeat`

No extra fields. Sent every 30 seconds while the session is open.

### `ticket.submit`

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | Generated by the mod |
| `text` | string | First 200 characters of the prompt, the scheduled prompt, or the task description |
| `origin` | string, optional | `user` (default), `schedule`, `task`, `unknown`. Says who issued the ticket. |
| `scheduleId` | string, optional | Set when `origin` is `schedule` |
| `taskIds` | string array, optional | Set when `origin` is `task`. Several tasks can finish before the same turn. |
| `parentTicketId` | string, optional | For `origin: task`: the ticket that started the first task in `taskIds`. The receiver sends the report to that ticket's issuer. |
| `messageKind` | string, optional | For `origin: unknown`: the turn starts with another agent's message, `report` (a subagent's final report) or `message` (one sent with SendMessage). `text` is then empty, and the receiver writes the note, such as "Report from planner". |
| `fromAgentId` | string, optional | With `messageKind`: the staff member the message is from, when the mod knows it; absent for another session or an unknown agent. |

A ticket with `origin` set to `unknown` is a main-agent turn that the mod could not trace to a prompt, a schedule, or a task. The receiver shows the Chief of Staff picking it up from an inbox tray, and the report goes to the CEO.

### `chief.hat`

Sent after task-type classification finishes.

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | |
| `taskType` | string | ID from `catalog/task-types.json` |

### `ticket.title`

Sent when a small model (Haiku) has named a typed prompt's task in a few words. The receiver shows it on the project block's sign while the ticket is open. It may be wrong; it is only a label. Not sent if the model gives no answer.

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | |
| `title` | string | Asked for at most 20 characters (10 for Chinese, Japanese or Korean), in the prompt's language; never more than 60 characters |

### `ticket.done`

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | |
| `durationMs` | integer | End-to-end time for the completion sound gate. For `origin: user`, it is Claude Code's duration for the main turn. For `task`, it is measured from the start of the earliest task in `taskIds`. For `schedule`, it is measured from the time the schedule fired, and for `unknown` from the start of the ticket. After `ticket.return`, it covers all of the work on the ticket. |
| `aborted` | boolean | `true` when the user interrupted |

### `ticket.return`

A hook stopped the main agent from ending its turn and sent it back to work (spec scene 15). The ticket stays open. A later `ticket.done` closes it.

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | |
| `reason` | string, optional | First 200 characters of the hook's reason, if the mod can read it |

### `staff.hire`

A message to a finished subagent resumes it, and it is hired again: another `staff.hire` with the same `agentId`, then its own `staff.done`. Receivers treat each hire as a new run of that staff member; a `staff.done` belongs to the latest run. The plugin sends the role the agent already had, with no new classification.

| Field | Type | Notes |
|---|---|---|
| `agentId` | string | |
| `parentAgentId` | string, optional | Set when a subagent starts another subagent |
| `subagentType` | string | Such as `general-purpose`, `Explore`, or a custom agent name. `main-loop` for a desk worker: not a subagent, but the main agent's own work on the open ticket, shown as staff the Chief of Staff called. Its `agentId` is `desk-<ticketId>-<n>`; a ticket can have several, one per role. The main agent's activities and approvals carry the `agentId` of the one with the work now; the others wait. Their `staff.done` events come together just before the ticket's `ticket.done` (or earlier for the one idle longest, past five) |
| `name` | string, optional | |
| `description` | string | First 200 characters |
| `teammate` | boolean | `true` for an agent-team teammate |
| `background` | boolean | |
| `model` | string, optional | The model the subagent runs on, as `agent.spawn` resolved it. When absent, the receiver uses the parent's current model (`parentAgentId`, or the main agent). |

### `staff.role`

Sent after role classification finishes.

| Field | Type | Notes |
|---|---|---|
| `agentId` | string | |
| `role` | string | ID from `catalog/roles.json`, or `generalist` |

### `staff.done`

| Field | Type | Notes |
|---|---|---|
| `agentId` | string | |
| `status` | string | `completed`, `failed`, `killed`, `aborted` |
| `durationMs` | integer, optional | |

### `model.update`

Sent when the model that answered a character's request differs from the last one sent for that character. Not sent for every request.

| Field | Type | Notes |
|---|---|---|

Sent after role classification finishes.

| Field | Type | Notes |
|---|---|---|
| `taskId` | string | |
| `role` | string | A background role ID from `catalog/roles.json`, or `background-worker` |

### `task.done`

| Field | Type | Notes |
|---|---|---|
| `taskId` | string | |
| `status` | string | `completed`, `failed`, `killed` |
| `durationMs` | integer, optional | |

### `schedule.create`

| Field | Type | Notes |
|---|---|---|
| `scheduleId` | string | Claude Code's schedule ID, or one generated by the mod |
| `text` | string | First 200 characters of the scheduled prompt |
| `recurring` | boolean | `false` for a one-time wakeup |
| `nextRunTs` | integer, optional | Unix milliseconds |

### `schedule.delete`

| Field | Type | Notes |
|---|---|---|
| `scheduleId` | string | |

A one-time schedule is also removed after it fires. Receivers remove all of a session's schedules on `session.close`.

### `message.send`

One agent sent a message to another (spec scene 16).

| Field | Type | Notes |
|---|---|---|
| `fromAgentId` | string, optional | Absent for the main agent |
| `toAgentId` | string, optional | Absent for the main agent. Set when the mod can resolve the receiver. |
| `toName` | string, optional | The receiver's name as given to the tool, when the mod cannot resolve an ID. The receiver matches it against `staff.hire.name`. |
| `broadcast` | boolean, optional | `true` when the message goes to every teammate. The sender stays at the desk and the bubble shows over all receivers. |

The message text is not sent.

### `activity`

| Field | Type | Notes |
|---|---|---|
| `agentId` | string, optional | Absent for the main agent |
| `kind` | string | `read`, `edit`, `shell`, `web`, `mcp`, `other` |
| `tool` | string | Tool name, for debugging |

### `approval.wait`

| Field | Type | Notes |
|---|---|---|
| `approvalId` | string | The tool use ID |
| `agentId` | string, optional | Absent for the main agent |
| `tool` | string | |
| `autoMode` | boolean, optional | `true` when the session is in auto mode, where a classifier rather than the user answers most asks. The app shows the wait but plays no sound. |

### `approval.end`

| Field | Type | Notes |
|---|---|---|
| `approvalId` | string | |
| `outcome` | string | `allowed`, `denied`, `unknown` |

### `compact.start`

The main conversation's compaction began (`/compact`, or the automatic one). A subagent's or an engine fork's compaction, and a background precompute, send nothing.

| Field | Type | Notes |
|---|---|---|
| `trigger` | string | `manual` (`/compact`), `auto`, `other` |

### `compact.end`

| Field | Type | Notes |
|---|---|---|
| `outcome` | string | `done`, `skipped` (a hook vetoed it), `failed` |
| `tokensBefore` | integer, optional | The conversation's size before, when `done` and known |
| `tokensAfter` | integer, optional | Its size after, when `done` and known |

### `context.update`

The main conversation's context window: sent at session start (the window), when its fill moves by a whole percent, when the effort of the main loop's model requests changes, and when a main-loop turn ends. Every field is optional; the app keeps the last value of each.

| Field | Type | Notes |
|---|---|---|
| `tokens` | integer, optional | Input tokens the last response was answered over |
| `window` | integer, optional | The context window's size, in tokens |
| `percent` | integer, optional | `tokens` over `window`, 0 to 100 |
| `effort` | string, optional | `low`, `medium`, `high`, `xhigh`, `max` |
| `lastTurnTokens` | integer, optional | The tokens the main conversation's last turn added: uncached input, cache writes and output, summed over its requests. Cache reads (the conversation re-sent at each step) are left out. Sent when a turn ends |

## Receiver rules

- Ignore unknown event types and unknown fields. This lets the mod add events without breaking older apps.
- An unknown `role` or `taskType` ID is shown as the raw ID, and a character with an unknown role wears the neutral outfit color.
- Events for a session that has not sent `session.open` create the session (the app may have started after the session).
- A `ticket.submit` with an unknown `parentTicketId`, or an unknown `scheduleId`, still creates the ticket. The report goes to the CEO.
- Reorder by `seq` within a short window (about 500 ms). After that, apply events as they arrive.

## Versioning

- `protocol` is an integer. Adding optional fields or new event types does not change it.
- Removing or changing the meaning of a field increases it. The app answers 426 to versions it does not support. It reads the `protocol` number before the rest of the batch, so a future version gets 426 even if its batch has another shape.
