# Protocol v1

The protocol between the claude-town mod (sender) and a claude-town app (receiver). It has no platform-specific parts except the location of the endpoint file. The JSON Schema for every event goes in `protocol/schema/`, and recorded event streams for tests go in `protocol/fixtures/`.

## Transport

- HTTP/1.1 `POST` to `http://127.0.0.1:<port>/v1/events`
- Header `Authorization: Bearer <token>`
- Header `Content-Type: application/json`
- Body: a batch

```json
{
  "protocol": 1,
  "events": [ { ...event }, { ...event } ]
}
```

Responses:

| Status | Meaning | Sender does |
|---|---|---|
| 204 | Accepted | Nothing |
| 401 | Wrong token | Re-read the endpoint file |
| 426 | Unsupported protocol version | Stop sending for this session; show one toast |
| Connection refused, timeout | App not running | Drop the batch; re-read the endpoint file on the next flush |

The sender never retries a batch. A lost event is acceptable; the heartbeat and later events correct the state.

## Endpoint file

The app writes this file when its server starts and deletes it on quit. Mode 0600.

```json
{
  "protocol": 1,
  "port": 51234,
  "token": "random-32-bytes-base64url",
  "pid": 4242,
  "app": "claude-town",
  "appVersion": "0.1.0"
}
```

| Platform | Path |
|---|---|
| macOS | `~/Library/Application Support/claude-town/endpoint.json` |
| Windows | `%APPDATA%\claude-town\endpoint.json` (future) |
| Linux | `$XDG_STATE_HOME/claude-town/endpoint.json` (future) |

## Event envelope

Every event has these fields:

| Field | Type | Notes |
|---|---|---|
| `type` | string | One of the types below |
| `sessionId` | string | Claude Code session ID |
| `seq` | integer | Per session, starts at 1, increases by 1. The receiver uses it to order events and spot gaps. |
| `ts` | integer | Sender clock, Unix milliseconds |
| `projectId` | string | Hash of the project identity (see [architecture.md](architecture.md)) |

## Event types

### `session.open`

| Field | Type | Notes |
|---|---|---|
| `projectName` | string | Repository or folder name |
| `surface` | string | `terminal`, `desktop`, `vscode`, `headless` |
| `ccVersion` | string | Claude Code version |
| `locale` | string, optional | If the mod can read it |

### `session.close`

| Field | Type | Notes |
|---|---|---|
| `reason` | string | `clear`, `resume`, `logout`, `prompt_input_exit`, `other` (from Claude Code) |

### `heartbeat`

No extra fields. Sent every 30 seconds while the session is open.

### `ticket.submit`

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | Generated by the mod |
| `text` | string | First 200 characters of the prompt |

### `chief.hat`

Sent after task-type classification finishes.

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | |
| `taskType` | string | ID from `catalog/task-types.json` |

### `ticket.done`

| Field | Type | Notes |
|---|---|---|
| `ticketId` | string | |
| `durationMs` | integer | Claude Code's duration for the main turn. Used for the completion sound gate. |
| `aborted` | boolean | `true` when the user interrupted |

### `staff.hire`

| Field | Type | Notes |
|---|---|---|
| `agentId` | string | |
| `parentAgentId` | string, optional | Set when a subagent starts another subagent |
| `subagentType` | string | Such as `general-purpose`, `Explore`, or a custom agent name |
| `name` | string, optional | |
| `description` | string | First 200 characters |
| `teammate` | boolean | `true` for an agent-team teammate |
| `background` | boolean | |

### `staff.role`

Sent after role classification finishes.

| Field | Type | Notes |
|---|---|---|
| `agentId` | string | |
| `role` | string | ID from `catalog/roles.json`, or `generalist` |

### `staff.done`

| Field | Type | Notes |
|---|---|---|
| `agentId` | string | |
| `status` | string | `completed`, `failed`, `killed`, `aborted` |
| `durationMs` | integer, optional | |

### `activity`

| Field | Type | Notes |
|---|---|---|
| `agentId` | string, optional | Absent for the main agent |
| `kind` | string | `read`, `edit`, `shell`, `web`, `mcp`, `other` |
| `tool` | string | Tool name, for debugging |

### `approval.wait`

| Field | Type | Notes |
|---|---|---|
| `approvalId` | string | The tool use ID |
| `agentId` | string, optional | Absent for the main agent |
| `tool` | string | |

### `approval.end`

| Field | Type | Notes |
|---|---|---|
| `approvalId` | string | |
| `outcome` | string | `allowed`, `denied`, `unknown` |

## Receiver rules

- Ignore unknown event types and unknown fields. This lets the mod add events without breaking older apps.
- Unknown `role` or `taskType` IDs fall back to `generalist` and `general`.
- Events for a session that has not sent `session.open` create the session (the app may have started after the session).
- Reorder by `seq` within a short window (about 500 ms). After that, apply events as they arrive.

## Versioning

- `protocol` is an integer. Adding optional fields or new event types does not change it.
- Removing or changing the meaning of a field increases it. The app answers 426 to versions it does not support.
